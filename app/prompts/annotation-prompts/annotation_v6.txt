GENERAL EXTRACTION RULES
1. "Persona" is the phrase after "As a" or "As an", without the article.
2. Use only facts stated explicitly in the user story. Do not invent actions, entities, attributes, or relations.
3. Every item in triggers, targets, and contains must be an array of exactly two strings.
4. Preserve exact wording from the text. Remove only articles and possessive determiners when they do not change meaning.
5. Never insert punctuation inside words.

ACTION EXTRACTION (applies to both GoalAction and BenefitAction)
1. An Action is a verb that acts on an Entity, or stands alone as an intransitive verb.
2. Preserve the exact verb form as it appears in the US text. Never change tense, aspect, or form:
   - "securely stored" → "stored" (not "store")
   - "are synced" → "synced" (not "sync")
   - "by entering" → "entering" (not "enter")
   - "without giving" → "giving" (not "give")
   - "only shows" → "shows" (not "show")
   - "remains uncluttered" → "remains" (not "remain")
3. Strip only surrounding adverbs, never the verb itself:
   - "securely stored" → "stored"
   - "quickly capture" → "capture"
   - "manually adjust" → "adjust"
   - "permanently delete" → "delete"
4. Preserve phrasal verbs exactly:
   - "sign up", "log in", "log out", "walk through", "re-watch"
5. A verb used only to describe an entity is NOT an action:
   - "saved spot" → "saved" is a descriptor, not an action
   - "generated itinerary" → "generated" is a descriptor, not an action
6. A verb found only inside a relative clause modifying a noun is NOT an action:
   - "tutorial that demonstrates how to import" → "demonstrates" is NOT an action
   - "trip I no longer need" → "need" is NOT an action
7. Negated verbs ("without X", "no X") are still captured as actions:
   - "without manually typing details" → Action: "typing", Entity: "details"
   - "without reading external documentation" → Action: "reading", Entity: "documentation"
   - "without manual scheduling" → Action: "scheduling" (no direct object, intransitive)
8. Split independent coordinated actions:
   - "stored and synced" → ["stored", "synced"]
   - "create named lists and add saved spots" → ["create", "add"]
   - "drag and drop stops" → ["drag", "drop"]

ENTITY EXTRACTION (applies to both GoalEntity and BenefitEntity)
1. An Entity is a noun phrase representing an element involved in the system.
2. Preserve the exact noun phrase form as it appears in the text.
3. Keep meaningful modifiers that distinguish the intended entity:
   - "saved spot", "private notes", "named lists", "travel data"
   - "read-only web link", "generated itinerary", "day-by-day itinerary"
4. Remove only articles and possessive determiners:
   - "my email" → "email"
   - "their account" → "account"
5. Split explicit coordinated entities:
   - "spots and trips" → ["spots", "trips"]
   - "start date, end date, or total number of days" → ["start date", "end date", "total number of days"]
6. A verb used to describe an entity is part of the entity, not a separate action:
   - "saved spot" → entity is "saved spot", not action "saved" + entity "spot"
   - "generated itinerary" → entity is "generated itinerary"
7. Every Entity in GoalEntity or BenefitEntity must be reachable by either:
   a. A targets-edge from an Action, OR
   b. A contains-edge from another Entity as a child
   An Entity that appears in neither targets nor contains as a child
   does NOT belong in GoalEntity or BenefitEntity.

GOAL CLAUSE SPECIFIC RULES
1. GoalAction contains verbs from the "I want to..." clause only.
2. GoalEntity contains the direct object noun phrases of GoalAction, plus
   any nouns explicitly listed as components or examples within the goal clause.
3. Normalize goal actions by stripping adverbs but preserving verb form:
   - "sign up using my email" → "sign up"
   - "log in my account" → "log in"
   - "manually add a spot" → "add"
   - "permanently delete a trip" → "delete"
   - "Submit Application" → "submit" (never include the object inside the action label)
4. When the user explicitly asks the application to perform an action
   ("have the app automatically generate..."), include the app action as a GoalAction.
5. Verbs found only in the "so that" benefit clause must NEVER appear in GoalAction:
   - "drag and drop stops, so that I can adjust the order"
     → GoalAction: ["drag", "drop"] ONLY
     → BenefitAction: ["adjust"] ONLY

BENEFIT CLAUSE SPECIFIC RULES
1. BenefitAction contains verbs from the "so that..." clause only.
2. BenefitEntity contains the direct object noun phrases of BenefitAction.
3. When no explicit "so that" clause exists, BenefitAction and BenefitEntity are empty:
   - BenefitAction: []
   - BenefitEntity: []
4. Verbs found only in the "I want to" goal clause must NEVER appear in BenefitAction.

RELATIONSHIP RULES
1. triggers: create [Persona, GoalAction] for every GoalAction.

2. targets: create [Action, Entity] for every explicit action-to-direct-object relation.
   - For coordinated entities, create a separate target pair for each entity.
   - An Action can appear in multiple target pairs if it acts on multiple entities.
   - An Action without a direct object (intransitive) has no targets-edge.

3. contains: create [ParentEntity, ChildEntity] pairs only when one entity truly
   contains another as a PART, COMPONENT, VALUE, or SUB-ELEMENT.

   DIRECTION RULE: always [ParentEntity, ChildEntity].
   The parent is the LARGER or CONTAINING entity.
   The child is the SMALLER or CONTAINED entity.

   Detect containment from these linguistic patterns:

   a. EXPLICIT INCLUSION ("including", "such as", "e.g.", "like"):
      "itinerary including maps, spot details"
      → ["itinerary", "maps"], ["itinerary", "spot details"]
      "private notes (e.g., reservation numbers or tips)"
      → ["private notes", "reservation numbers"], ["private notes", "tips"]

   b. SYSTEM/UI HIERARCHY (a system contains its elements):
      "publish button in FABS" → ["FABS", "publish button"]
      "files from FABS" → ["FABS", "files"]

   c. DATA HIERARCHY (a record contains its fields or values):
      "updates to FABS records" → ["FABS records", "updates"]
      "zero and blank for loan records" → ["loan records", "zero"], ["loan records", "blank"]

   d. PARTITIVE phrases ("X of Y" → Y contains X):
      "name of an existing list" → ["existing list", "name"]

   e. RELATIVE CLAUSE entities ("X that demonstrates/includes Y, Z"):
      The described items are contained within the parent entity:
      "tutorial that demonstrates how to import a spot, create a list"
      → ["tutorial", "spot"], ["tutorial", "list"]

   STRICT RULES for contains:
   - Both elements MUST be nouns (entities) from the US text
   - Ask: "Is [child] truly a part/component/value of [parent]?"
     YES → add to contains
     NO  → do not add
   - Child entities in contains do NOT need to appear in GoalEntity or BenefitEntity
   - PURPOSE ("for offline use") → NOT contains
   - CONDITION ("without internet") → NOT contains
   - LOCATION ("on a map") → NOT contains
   - METHOD ("by entering") → NOT contains
   - TIME ("before visiting") → NOT contains

4. Do not add a relation when it is merely implied rather than stated.
