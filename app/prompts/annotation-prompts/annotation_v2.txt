GENERAL EXTRACTION RULES
1. Return exactly the 9 required top-level keys and no extra keys.
2. "Text" must copy the original input story character-for-character.
3. "Persona" is the phrase after "As a" or "As an", without the article. Adjectives are included in the persona Public User and not only User
4. Use only facts stated explicitly in the user story. Do not invent actions, entities, attributes, or relations.
5. Every item in triggers, targets, and contains must be an array of exactly two strings.
6. Preserve exact wording where required, but remove only articles and possessive determiners when they do not change the entity meaning.
7. Never insert punctuation inside words. For example, write "trips", never "tr,ips".

GOAL ACTION EXTRACTION
1. GoalAction contains the canonical action labels (an action - verbs) requested by the user in the "I want to" clause.
2. Use the shortest meaningful base verb or phrasal-verb label. Never include an object, article, adverb or context phrase in an action label. Adjectives are included in the action "quickly upload" and not only "upload"
3. Preserve phrasal verbs exactly:
   - "sign up"
   - "log in"
   - "log out"
   - "walk through"
   - "re-watch"
4. Normalize:
   - "sign up using my email" -> "sign up"
   - "log in my account" -> "log in"
   - "log out when I am finished" -> "log out"
   - "manually add a spot" -> "add"
   - "quickly capture travel inspiration" -> "capture"
   - "permanently delete a trip" -> "delete"
   - "view the generated itinerary" -> "view"
   - "change the name of a list" -> "change"
5. Split independent coordinated goal actions:
   - "create named lists and add saved spots" -> ["create", "add"]
   - "copy an itinerary and adjust dates" -> ["copy", "adjust"]
   - "drag and drop stops" -> ["drag", "drop"]
6. Do not extract verbs found only inside a descriptive relative clause.
   Example: in "walk through a tutorial that demonstrates how to import a spot, create a list, and generate an itinerary", the GoalAction is only ["walk through"].
7. When the user explicitly asks the application to perform an action by using a construction such as "have the app generate...", include the app action as a GoalAction.

GOAL ENTITY EXTRACTION
1. GoalEntity contains direct noun phrases affected by a GoalAction.
2. Prefer the exact semantic object, not the whole clause:
   - "change the name of an existing list" -> ["name"]
   - "filter the map to show spots" -> ["map"]
   - "view the generated itinerary" -> ["generated itinerary"]
3. Keep meaningful modifiers when they distinguish the intended object:
   - "saved spot"
   - "saved spots"
   - "private notes"
   - "named lists"
   - "travel data"
   - "read-only web link"
   - "generated itinerary"
   - "day-by-day itinerary"
4. Remove nonessential articles and possessives:
   - "my email" -> "email"
   - "an existing list" is contextual to "name", not a GoalEntity by itself.
5. Split explicit coordinated entities:
   - "spots and trips" -> ["spots", "trips"]
   - "start date, end date, or total number of days" -> ["start date", "end date", "total number of days"]
   - "destination, travel dates, and a list of saved spots" -> ["destination", "travel dates", "list of saved spots"]
6. Expand explicit alternatives that share one head noun:
   - "Google/Apple account" -> ["Google account", "Apple account", "Google/Apple account"]
   - "TikTok or Instagram video" -> ["TikTok video", "Instagram video", "TikTok or Instagram video"]
7. When two goal actions share one explicit object, include the object once in GoalEntity but create one target relation for each action.

BENEFIT ACTION AND BENEFIT ENTITY
1. BenefitAction contains canonical actions from the "so that" clause.
2. BenefitEntity contains the direct objects of BenefitAction.
3. Normalize benefit actions by removing adverbs:
   - "securely stored" -> "stored"
   - "quickly capture" -> "capture"
   - "manually adjust" -> "adjust"
4. Split coordinated benefit actions and entities when explicit:
   - "stored and synced" -> ["stored", "synced"]
   - "understand distribution and plan routes" -> ["understand", "plan"] with ["spatial distribution", "routes"]
5. Do not put contextual objects such as devices, maps, lists, locations, or timing phrases into BenefitEntity unless they are the direct object of a benefit action.

RELATIONSHIP RULES
1. triggers: create [Persona, GoalAction] for every GoalAction.
2. targets: create [Action, Entity] for every explicit action-to-direct-object relation.
3. For alternatives or coordinated entities, create a separate target pair for each explicit entity.
4. contains: create relations between 2 nous phrases [PrimaryPhrase, ContextPhrase] - Primary structurally has Context as a part, attribute or member.
5. Examples of valid contains pairs:
   - ["spot", "name"]
   - ["existing list", "name"]
   - ["list", "saved spots"]
   - ["trip", "start date"]
   - ["generated itinerary", "daily route"]
   - ["map", "daily route"]
   - ["itinerary", "spot details"]
6. Noun phrases new to GoalEntity and BenefitEntity that only appear through a contains relation must also be added to GoalEntity (if part of the Goal clause) and BenefitEntity (if part of the Benefit clause).
7. Do not add a relation when it is merely implied rather than stated.
