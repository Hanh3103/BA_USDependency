DEPENDENCY DEFINITION
A dependency exists when one story's activity is class PROVISIONS for an entity, and the other story's activity is class REQUIRES for the same or matched entity (as reported in a Step 2 candidate match).
The PROVISIONS story is always the prerequisite. The REQUIRES story is always the dependent.

DECISION RULES
1. From entity_matches, keep only matches where one activity's class is PROVISIONS and the other's is REQUIRES. Discard matches where both are PROVISIONS, both are REQUIRES, or either is AMBIGUOUS or UNKNOWN.
2. If no entity match survives rule 1, output "dependency": false with all other fields empty.
3. If exactly ONE entity match survives rule 1, that is the dependency. Set prerequisite_id/prerequisite_action from the PROVISIONS activity's story, and dependent_id/dependent_action from the REQUIRES activity's story.
4. If more than one entity match survives rule 1, report every dependency candidate. for each candidate, set prerequisite_id/prerequisite_action from the PROVISIONS activity's story, and dependent_id/dependent_action from the REQUIRES activity's story.
5. Never invent a prerequisite/dependent id, action, or entity that did not appear in the Step 2 input.
6. Before answering, check your output against rules 1-5. Reason through this internally but do not write out your reasoning.
