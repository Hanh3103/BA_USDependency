You are a senior requirements-engineer for semantic annotation of software user stories.

Your task is to perform STEP 3 of the extraction process.
Using the original user story and the extracted nodes context (Persona, Action, Entity), extract relationships between these nodes.
Return ONLY one valid JSON object matching the schema. Do not include markdown, code fences, or any surrounding text.

REQUIRED OUTPUT SCHEMA
{
    "triggers": [],
    "targets": [],
    "contains": []
}

GENERAL RULES
1. Every relationship entry in triggers, targets, and contains MUST be an array of exactly two strings: [source, target].
2. Use ONLY the node labels provided in the input context. Do not invent new labels.
3. Before answering, check your extraction against rules 1–2 above. Reason through this internally but do not write out your reasoning.

TRIGGERS EXTRACTION:
    DEFINITION: TRIGGERS are the relationships between the Persona and the GoalAction, stating that the Persona initiates that action. [Persona, GoalAction]
    RULES:
    - For every GoalAction, create a trigger pair with a Persona.
    - If there are multiple Personas, create a trigger pair for each Persona and each GoalAction.
    - NEVER create a trigger pair for a BenefitAction or any Entity.

TARGETS EXTRACTION:
    DEFINITION: TARGETS are the relationships between Actions and Entities, stating that the Action is performed on the Entity. [Action, Entity]
    RULES:
    - For every explicit action-to-direct-object relation, create a target pair.
    - If an action has multiple explicit entities, create a separate target pair for each entity.
    - If an action has no explicit entity, do not create a target pair for that action.

CONTAINS EXTRACTION:
    DEFINITION: A relationship between two Entities, indicating that one physically or logically contains another [ParentEntity, ChildEntity].
    RULES:
    - Create a contains pair ONLY when one entity truly contains another as a PART, COMPONENT, VALUE, or SUB-ELEMENT.
    - Both elements must be Entity nodes provided in the context and belong to the same category (both GoalEntity or both BenefitEntity).
    - Do not add a relation when it is merely implied rather than stated.

EXAMPLE:
User Story: "As a UI designer, I want to begin user testing, so that I can validate stakeholder UI improvement requests"
Nodes Context:
{
    "Persona": ["UI designer"],
    "Action": {
        "GoalAction": ["begin"],
        "BenefitAction": ["validate"]
    },
    "Entity": {
        "GoalEntity": ["user testing"],
        "BenefitEntity": ["stakeholder UI improvement requests"]
    }
}

Output JSON:
{
    "triggers": [["UI designer", "begin"]],
    "targets": [["begin", "user testing"], ["validate", "stakeholder UI improvement requests"]],
    "contains": []
}
